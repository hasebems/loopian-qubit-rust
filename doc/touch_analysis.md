# タッチ解析（複数の電極から 1 つのタッチを求め、演奏情報を取り出す） 設計書

2026-11-08 書き始め。2026-11-14 に、対応済みの項目・古い実装の記録を削除して整理した（古い内容は git の履歴にある）。

## 1. 背景と目的

### 1.1 本書の範囲

タッチの処理は、次の 2 段に分かれる。

| 段 | 扱うもの | 実装 | 設計書 |
|---|---|---|---|
| 信号処理 | 電極 1 つずつ。ノイズ除去・基準値・noise_floor を扱い、電極毎の output を出す | `crates/touch_algo` の `electrode.rs`（`ElectrodeSignal`） | `doc/touch_baseline.md` |
| 解析（本書） | 複数の電極の output から 1 つのタッチを求め、そこから演奏情報（ノート・ベロシティ・ビブラートなど）を取り出す | `crates/touch_algo` の `touch.rs`（`TouchTracker`: depth・position）と `playinfo.rs`（`PlayInfo`: 演奏情報）（§5） | 本書 |

入口は `doc/touch_baseline.md` §3.9 の受け渡し（`ElectrodeSignal::process()` の output を `TouchTracker::set_value()` で渡す）である。

### 1.2 目標

1. 1 本の指のタッチを、1 つのタッチとして求める。そのタッチは depth と position の 2 つの情報を持つ（§3）
2. 求めたタッチから演奏情報を取り出す（ノート・ベロシティ・ビブラートなど。§4）
3. 複数の指（最大 `MAX_TOUCH_POINTS` = 4 点）を扱う。決め打ちの距離以内の指は分けない（§3.7）

## 2. 用語

| 用語 | 意味 |
|---|---|
| 電極 | タッチセンサの 1 つの電極（electrode）。AT42QT1070 の 1 チャンネルに当たる。`touch_algo` の output が電極毎に 1 つある。データシート・`doc/touch_baseline.md`・ファームのコードの多くでは key（キー）と呼んでいるが、本書では電極と呼ぶ |
| output | `touch_algo` が電極毎に出す値。`delta − noise_floor`（0 未満は 0）。未タッチで 0、触れると正（`doc/touch_baseline.md` §2） |
| タッチ | 1 本の指が触れていることを表すもの。隣り合う複数の電極の output から 1 つ求める。**タッチは指 1 本の単位だけに使い、電極 1 つの反応はタッチと呼ばない**（「電極が反応する」と言う）（2026-11-08 決定） |
| depth | タッチの深さ。指がどれだけ強く・広く触れているかを表す量（§3.2） |
| position | タッチの位置。電極番号を単位とする実数（電極間の位置も表す）（§3.3） |
| 区間 | output が k（`SEGMENT_THRESHOLD`）より大きい電極が続く範囲（§3.4） |

## 3. タッチの層（`touch.rs`）

### 3.1 考え方

1 本の指は、電極の幅より広いので、隣り合う複数の電極（2〜3 個程度）にまたがって触れる。電極毎の output を個別に見るのではなく、まとめて **1 つのタッチ** とし、depth と position で表す。演奏情報（§4）は、この 2 つの量とその時間変化から取り出す。電極毎の output は、ここから先の処理には直接使わない。

### 3.2 depth（2026-11-08 決定）

**1 本の指とみなした電極（§3.4 の区間）の output を、すべて足したもの。**

```
depth = Σ output[k]    （k は 1 本の指とみなした電極）
```

- 指の押しつけの強さと、触れている面積の両方を含む量になる
- **output をそのまま足した線形の量とし、テーブルなどで変換しない（2026-11-12 決定）**。depth は有無の判定（§3.5）にも使うため。強調が要るなら、演奏情報の層で速さを求めるとき（§4.2）に考える
- 合計は `i32` で取り、`i16::MAX` で頭打ちにして返す

### 3.3 position（2026-11-08 決定）

**1 本の指とみなした電極の output の重心。**

```
position = Σ (k × output[k]) / depth
```

- 単位は電極番号で、電極の間の位置も実数で表す
- 足す電極は depth と同じ（§3.4）
- リングでは 0 以上 96 未満に巡回させる（§3.6）

### 3.4 1 本の指とみなす電極の範囲: 区間（2026-11-13 方針・実装）

**output が k より大きい電極が続く区間を、1 つの候補とする。depth・position は、その区間の電極の output をそのまま使って求める。**

- 区間は、k 以下の電極で区切る。k は区間を決めるためだけに使い、depth・position は区間の中の output をそのまま足して求める（k を引いたりしない）
- k を 0 にしない理由: 2 本の指の間や区間の端に 1〜2 の小さな output が残ると、離れた指がつながったり、ノイズの電極が区間に入って position がずれたりするため
- 窓で切らないので、指を寝かせて幅広く触れても depth が欠けない。平らな頂上や、1 本の指で山が 2 つできる場合も、区間が 1 つなら 1 つの候補になる
- 端の電極が k を超えた瞬間に区間に入るので、position が少し跳ねる（大きさは k × 中心からの距離 / depth 程度）

実装（`crates/touch_algo/src/touch.rs`）:

- `SEGMENT_THRESHOLD`（k）= 5。「より大きい」で比べる。値は見当をつけずに決めた（ユーザーの判断）
- `scan_segments`: 区間毎に `candidate(先頭, 終わり)` で depth・position を求める。1 周期に `MAX_CANDIDATES`（16）個まで取り、超えたら depth の小さいものを捨てる
- リングでは、k 以下の電極から走査を始めるので、つなぎ目をまたぐ区間も 1 つになる。全部の電極が k を超えたときは、全体を 1 つの区間にする
- 2026-11-13 確認: qubit_etude（etude の実機）で触れてみて、問題ないように見えることをユーザーが確かめた

記録（`qubit_20261111_225627.qlog`、12 キーの端の電極 10〜11 を軽く触れている）で気づいたこと。実際の演奏で困ることがあれば扱う（§9）:

- 電極 10（output 3〜5）が k 以下で区間に入らず、position が 11.00 に張り付き、ノートも変わった。軽く触れたときは、端の電極が k 以下になりやすく、position が電極の位置に寄る
- 記録の最後まで電極 11 が 7〜8 のままで、指が離れない。指がまだ軽く触れていたのか、離した後に output が残っていたのかは、この記録だけでは分からない。後者なら、k が OFF のしきい値になっているので、残った output で指が離れない

### 3.5 タッチの有無の判定（2026-11-13 方針・実装）

**指の有無は depth で決める。指の検出と Note On/Off は連動させない（Note On/Off は §4.2）。**

- **触れ始め**: 区間の depth が `TOUCH_ON_DEPTH`（10、「より大きい」）を超え、近くに追跡中の指が無ければ、新しい指にする（`Started`）。山の電極 1 つの output では決めない。指が 2 つの電極のちょうど間にあると output が割れて山が小さくなり、触れる場所で感度が変わるため
- **続き**: 追跡中の指の近く（`CLOSE_RANGE` = 3 電極以内）に区間があれば、depth によらず同じ指が続いているとする（`Followed`）。区間は output > k で決まるので、OFF のしきい値は k の所にあることになり、ON のしきい値との差がヒステリシスになる
- **途切れ**: 近くに区間が無いときは、最後に見つけてから `RELEASE_WAITING_US`（50ms）の間だけ指を保持し、それを超えたら離れたとする（`Released`）。保持している周期（`Track::None` で `is_touched()` が true）の depth・position は、最後に見つけた周期の値のまま。演奏情報の層は、この周期の depth を履歴に入れない（§4.2）
- 区間で探せば、見つけられない周期は、depth が本当にほぼ 0 の周期だけになる。ゆっくり離すときの depth の下がり方は、`Followed` の間にすべて見える
- 検出のしきい値は低めにする。演奏情報の層は depth の立ち上がりから触れる速さを求める（§4.2）ので、立ち上がりの始めから depth を渡したい
- 同じ指を同じ TouchPoint に保つ仕組みは、タッチの層に置く。検出が途切れて Released → Started になると、演奏情報の層からは別の指に見え、速さの計測や位置の履歴がやり直しになるため
- 結び付け（`track_touch_points`）: 候補を depth の大きい順に、まだこの周期で更新していない TouchPoint のうち position の最も近いものと結び付ける

ヒステリシス: 前の状態（触れている / いない）に応じて、しきい値を 2 つ使い分けること。値そのものには手を加えないので、平滑化と違って遅れない。`RELEASE_WAITING_US` は、同じ揺れを時間で待って抑えるやり方にあたる

検討して取り下げた案（2026-11-13）: 保持している周期にも、最後の position の窓で output を足し直して depth を渡す。タッチの層の中に depth の求め方が 2 通りできて、どちらで求めた値かで depth の意味が変わるため。区間で探して、見つけられない周期そのものを減らすほうを選んだ

### 3.6 リングのつなぎ目（2026-11-08 方針）

**depth・position を求めることと、それを演奏情報にすることを分ける。**

- **depth・position**: つなぎ目をまたいでも、ほかの場所の指と同じように 1 本のタッチとして、同じ精度で出す（position は 0 以上 96 未満に巡回させる）。つなぎ目だからといって特別な処理はしない
- **演奏情報**: つなぎ目をまたいだときの扱いは、演奏情報の側で決める（§4.1）
- リングかどうかは `TouchTracker::new` の引数 `ring` で渡す。ファームは `constants.rs` の `TOUCH_RING`（96 電極だけ true）、PC アプリはキー数が 96 のときだけ true。リングでない構成（etude・no_pca9544）では、両端の外側を output 0 の電極として扱う
- リングでは距離を近い向きに測る（`Layout::distance`。例: 96 電極で 95.8 と 0.1 は 0.3）。結び付け・ノートを変えるヒステリシスで使う。指がつなぎ目を越えても同じタッチのまま続く

### 3.7 近い複数の指（2026-11-08 決定）

**ある距離以内にある複数の指は、分けて認識しない。1 本のタッチとして扱う。**

- 指を電極の並びに沿って寝かせて触れれば、1 本の指でもいくらでも幅広く触れられる。これと、近くに並べた複数の指を、このセンサで見分けることはできない
- 複数の指を分けて認識するのは、その距離より離れているときだけ

#### 3.7.1 決め打ちの距離とヒステリシス（2026-11-13 方針・実装）

区間で探すと、間に k 以下の電極が 1 つでもあれば、近くても 2 本に分かれる。境目で 1 本と 2 本を行き来し、Move が往復するのを qubit_etude でユーザーが見た（2026-11-13）。そこで、**近い区間を決め打ちの距離でまとめる。まとめる距離と分ける距離に差をつけて、ヒステリシスにする。**

- 隣り合う区間の position の差が距離 D 以内なら、1 つの候補にまとめる。まとめた候補の depth・position は、左の区間の先頭から右の区間の終わりまで（間の k 以下の電極も含めて）の output から求め直す
- D は、前の周期の指の数で変える（`merge_limit`）。2 つの区間の position の間（外側へ `MERGE_COUNT_MARGIN` = 1 電極広げる）に、前の周期の指（離れるのを待っているものも含む）が
    - 1 本だけあった: D = `SPLIT_DISTANCE`（7 電極）。これより離れるまで 1 本のまま
    - 2 本以上あった、または 1 本も無かった: D = `MERGE_DISTANCE`（4 電極。初めは 6 だったが、区間で探すと遠すぎたので 4 にした）
- 値はひとまずこれでよしとした（2026-11-13、ユーザー）
- `update` の流れ: `scan_segments`（区間を電極の順に取る）→ `merge_segments`（まとめる）→ depth の大きい順に並べる → `track_touch_points`（結び付け）→ `release_touch_points`（離れたかの判断）
- `merge_segments`: 電極の順に、まとめた候補から右へ次の区間までの距離（`Layout::ahead`。近い向きで測ると、リングの走査の始めと終わりにある区間を遠回りの範囲でまとめてしまうため）が D 以内ならまとめる。リングでは最後に、最後の候補と最初の候補をつなぎ目をまたいで 1 回だけ比べる（まとめた結果が、さらにその隣とまとまる場合は扱っていない）
- ヒステリシスの性質上、1 本の指の近くに、別の指を 4〜7 電極の距離で新しく置くと、1 本にまとめる
- 距離は position の差（重心どうし）で測る
- まとめたときに position が真ん中に跳ぶこと（2 本 → 1 本）と、分けたときに跳ぶこと（1 本 → 2 本）は残る。演奏情報の層での扱いは §4.2 の未決

### 3.8 時間は実時間で数える（2026-11-13 決定・実装）

**タッチの層と演奏情報の層の時間は、解析の周期の数ではなく、実時間（µs）で数える。** 解析が 10ms 毎に呼ばれなくても（96 キーでスキャンが 10ms を超える、`hw96_check.md` §2.1）、時間の感覚がずれないようにする。変わるのは時間の分解能だけになる。

- `TouchTracker::update(now_us)` に今の時刻を渡す。`PlayInfo` は `TouchTracker::now_us()` を使う。時刻は u32 の µs（約 71 分で一周）で、差は `wrapping_sub` で求める
- 呼び出し側: ファームは `cycle_start`（スキャンを始めた時刻。`signal.process` と同じ）、qubit_etude はフレームの時刻を渡す
- 実時間で数えるもの: 指を保持する時間（`RELEASE_WAITING_US`）、Note On までの経過と上限の時間（`NOTE_ON_TIMEOUT_US`）、ベロシティの補間、ビブラートの周波数（位置の履歴の各サンプルの時刻 `history_time_us` から求める）
- サンプルの数のままにするもの: `electrode` の中央値フィルタと平滑化（ノイズ除去の効き方はサンプルの数で決まる性質のため）
- テスト: `release_waits_real_time`・`velocity_follows_real_time`

## 4. 演奏情報の層（`playinfo.rs`）

### 4.1 リングのつなぎ目での扱い（2026-11-08 決定・実装）

- **Move（ノートの移動）**: つなぎ目をまたぐ Move はしない。ノートの番号が半周（ノートの数 / 2）より大きく変わったら、つなぎ目を越えたとして `cross_seam`、そうでなければ `move_note` を呼ぶ。番号で見るので、position はつなぎ目を越えていなくてもノートが越えた場合も含む
- **つなぎ目を越えて進んだ指**: Move せず、前のノートの Note Off（`STATUS_NOTE_OFF`）→ 越えた先のノートの Note On の順に出す。Move とほとんど同じイベントだが、後で Move に何かを足すことがあるので、別の関数にしてある。タッチ（TouchPoint）は同じものが続く
- **position が 95.5 以上で新しく触れたとき**: ノートは 0（四捨五入でノートの数になったら巡回させる）
- **Vibrato**: どれかの指の position が電極数 − 1 以上（96 電極では 95 以上）の間は、検出した値を出さない（CC を送らず、`vibrato()` も前の値のまま）。位置の履歴にはそのまま入れる

### 4.2 Note On / Note Off（2026-11-12・11-13 決定）

**指を検出しても、すぐには Note On を出さない。触れる速さ（depth の立ち上がり）を測ってから出す。Note Off も、指の検出とは連動させず、離すときの遅さを求める。**

- 速さを測るのに使う depth は、線形の depth（§3.2）
- **ベロシティで変えたいのは音量ではなく、音の立ち上がり（アタック）**（2026-11-13、ユーザー）
- **チャタリングへの効き目**: Note On を出す前に消えた短い反応は、Note On にならない。抑えられるのはノートの揺れで、指の追跡の揺れは §3.5 のとおりタッチの層で抑える
- **Note On の後は、しばらく音程を変えない**: Note On を出してから一定の時間は、position が動いてもノートを変えない（Move しない）。触れ始めの指の揺れでノートが動かないようにするため（**未実装**。手順 3）
- **Note Off**: 離すときの遅さ（depth の下がり方）を検出し、速く離したか、ゆっくり離したかを区別したい（**未決**。今は `Released` の周期に Note Off を出す）

#### Note On の出し方（2026-11-13 決定・実装）

**決め打ちの時間を待つのではなく、depth が `NOTE_ON_DEPTH` に届くまで待ち、届くまでの時間を測る。** 通常の鍵盤楽器のベロシティとは考え方が違い、速い側は頭打ちにして、遅い側の違いをしっかり取る。

| 触れ方 | depth の動き | Note On を出す周期 | ベロシティ |
|---|---|---|---|
| 速く押す | すぐに `NOTE_ON_DEPTH` を超える | 超えた周期 | 最大。ある速さより速いものは同じとみなす |
| ゆっくり押す | 時間をかけて `NOTE_ON_DEPTH` を超える | 超えた周期 | かかった時間で下げる。ここを細かく取る |
| はじく | `NOTE_ON_DEPTH` に届かないまま、すぐ下がる。ただし最大の depth は `FLICK_DEPTH` を超えている | 下がり始めた周期 | 速いとみなす |
| かすっただけ | `FLICK_DEPTH` を超えないまま消える | 出さない | — |
| 軽く触れたまま | `NOTE_ON_DEPTH` に届かず、下がりもしない | 上限の時間が過ぎた周期 | 遅いとみなす |

- 時間は、指を検出した周期（`Started`、§3.5）から数える。指を保持している周期（`Track::None`）も数える
- 速い側は頭打ちにするので、10ms 毎の分解能でよい（しきい値を超えた時刻の補間は要らない）
- 「はじく」の Note On は、`Released` を待たずに下がり始めた周期に出す（`Released` は指を失ってから 50ms 後なので、待つと遅れる）。Note Off は `Released` の周期に出す
- 「はじく」か「かすっただけ」かは、最大の depth が `FLICK_DEPTH` を超えたかどうかで決める（ユーザーの判断）

値（2026-11-13。数値の見当はつけずに、まず試す）:

- `FLICK_DEPTH` = 50、`NOTE_ON_DEPTH` = 70（どちらも「より大きい」）
- 下がり始め: depth が前の周期より下がった瞬間（幅は持たせない）。指を見失った周期（`Track::None` で触れている）も、下がったとみなす
- 上限の時間: `NOTE_ON_TIMEOUT_US` = 300ms
- ベロシティ（`onset_velocity`）: 経過 0 で `VELOCITY_FAST`（100）、上限の時間で `VELOCITY_SLOW`（30）。その間は時間で線形に補間する。はじいたときは 100、上限の時間が過ぎたときは 30
- Move の Note On は `VELOCITY_MOVE`（50）で固定（2026-11-13、ユーザー）。つなぎ目を越えたときは、その指の Note On のベロシティ
- 動作モード（Piano / Violin）は 2026-11-13 に無くした（ユーザー）。Violin の形（電極 `ELECTRODES_PER_NOTE` = 2 つで 1 ノート、ch 2、ノート 0 = `NOTE_OFFSET` 55）だけにし、Piano の処理は後で足す
- ノートを変えるのは、今のノートから position が `HISTERESIS`（0.7 電極）を越えて離れたとき

#### `PlayInfo` の流れ（2026-11-13 実装）

`PlayInfo::update(&tracker)` は、周期毎に `TouchPoint` 毎の `Track`・depth・position を受け、`Voice` 毎に状態（`VoiceState`）を進める（`perform_notes`）。

| 状態 | 入ってくる Track | すること |
|---|---|---|
| 待機（`Idle`） | `Started` | 測定中へ（`start_onset`） |
| 測定中（`Onset`） | `Followed` | 最大の depth と前の周期の depth を更新し、`Voice::onset` で Note On を出すか決める（上の表）。出したら発音中へ |
| 測定中 | `None`（保持中） | `Voice::onset_lost`: 最大の depth が `FLICK_DEPTH` を超えていれば、はじいたとして Note On |
| 測定中 | `Released` | 何も出さずに待機へ（かすっただけ） |
| 発音中（`Sounding`） | `Followed` | 位置の履歴に入れる。ノートが変わったら Move（`move_note` / `cross_seam`） |
| 発音中 | `Released` | Note Off → 待機へ |

- `Started` が来たら、その `Voice` は新しい指として初めからやり直す。位置の履歴も今の position で埋める
- 保持している周期（`Track::None`）は depth を履歴に入れない。その周期の depth は、最後に見つけた周期の値のままで、その周期に測った値ではないため（§3.5）
- 「離す測定中」の状態は作っていない。depth が下がっていくのは `Released` の前の `Followed` の間なので、発音中の depth から離すときの遅さを求められる。状態が要るかは、遅さの求め方を決めるときに判断する
- ビブラート（CC1・CC19）: 検出のコード（`update_vibrato`、1.5〜8Hz の往復）は残し、`set_vibrato_enabled`（既定 false）で止めている
- テスト: 速く押す・ゆっくり押す・軽く触れたまま・はじく（下がった周期と、見失った周期）・かすっただけ・Move・ベロシティの線形と実時間・つなぎ目・ビブラート
- 記録を `replay_algo` に通した結果: `qubit_20261027_211117.qlog` は Note On 2 件で、どちらもベロシティ 90 前後（`NOTE_ON_DEPTH` に届くまで 4 周期）。`qubit_20261111_225627.qlog`（軽く触れたまま）は、上限の時間でベロシティ 30 の Note On 1 件

#### 手順

1. 状態（待機・測定中・発音中）を作る — 2026-11-13 済み
2. Note On の出し方（`NOTE_ON_DEPTH` に届くまでの時間、はじく、上限の時間）を入れる — 2026-11-13 済み
3. **音程を変えない時間を入れる — 未実装**

## 5. 層の分け方（2026-11-08）

depth・position の層（§3）はノートを知らない。演奏情報の層（§4）は電極の output を見ない。呼び出し側は、毎周期 `TouchTracker::update(now_us)` → `PlayInfo::update(&tracker)` の順に呼ぶ。

| 層 | ファイル・型 | 持つもの |
|---|---|---|
| depth・position | `touch.rs` の `TouchTracker` | 電極の output、`TouchPoint`（指毎）: position・depth・最後に見つけた時刻・この周期の追跡の結果 `Track`（`Started`・`Followed`・`Released`・`None`） |
| 演奏情報 | `playinfo.rs` の `PlayInfo` | コールバック、`Voice`（指毎）: 状態・鳴らしているノート・測定中の最大の depth と前の周期の depth・Note On のベロシティ・位置の履歴（ビブラート用） |

- `PlayInfo` が `TouchTracker` から読むのは、指毎の `track()`・`get_location()`・`last_location()`・`get_intensity()` と、電極の並び（電極数・リングか）と `now_us()` だけ
- 離れた後も `TouchPoint` は最後の position を残す（`last_location()`。Note Off のコールバックの location に使う）。`get_location()` は、触れていなければ 100.0 を返す
- 共有状態（`TOUCH0-3`・`ANY_TOUCH`・`DEBUG_VALUE`）は、ファームの `touch_task` が両方の結果を読んで書く。`lighten_leds` と `TOUCH0-3` はタッチの層から作るので、ノートを遅らせても指の検出のとおりに点く
- MIDI の出力はコールバック `Fn(status, note, velocity, location)`。status は `STATUS_NOTE_ON`（0x90）・`STATUS_NOTE_OFF`（0x80）・`STATUS_NOTE_MOVED`（0xa0。ノートが変わったときの古いノートの Note Off）・`STATUS_CC`（0xb0）。ファームのコールバックはチャンネルを足して `MIDI_TX` に入れ、PC ではイベントを溜めて表示する

## 6. 残っている問題点

コードを読んで見つけたもの（2026-11-08）で、まだ対応していないもの。「確実」はコードから必ず起きると言えるもの、「おそれ」は条件によって起きるもの。

1. **noise_floor の大きい電極（おそれ）**: output は `delta − noise_floor` なので、noise_floor の大きい電極（etude の key5 は 13、他は 1〜2）は、同じように触れても output が小さい。position がその電極から離れる向きにずれ、depth も小さくなる。output が k 以下に落ちると区間が 2 つに分かれる（§3.7.1 の距離以内ならまとまる）
2. **電極による感度の違い（おそれ）**: noise_floor の他に、電極の大きさ・配線の長さ・チップ毎の違いで、同じ触れ方でも delta の大きさが電極で違う可能性がある。position の偏りになる。96 電極の基板で確かめる
3. **離れてから 50ms は同じタッチ（確実）**: 離れても `RELEASE_WAITING_US` の間は TouchPoint が残るので、その間に `CLOSE_RANGE`（3 電極）以内を叩き直すと、新しいタッチにならない。同じ電極を叩き直すと Note On が出ない（連打が抜ける）。近くの電極を叩くと Move になる
4. **結び付けが貪欲法（おそれ）**: 候補を depth の大きい順に、その時点で最も近い TouchPoint に結び付ける。2 本の指が近づいたとき入れ替わることがある。§3.7 の距離以内の指はまとめるので、起きうるのはそれより離れた指どうしだけ
5. **TouchPoint が空いていないとき（確実）**: 4 個とも使っている（離れるのを待っているものを含む）と、新しい候補は何も言わずに捨てられる（depth の大きい順に渡すので、捨てられるのは弱いほう）

## 7. 実装の場所（2026-11-08）

解析も `touch_algo` と同じく、ファームと PC アプリ（qubit_etude）で同じコードを使う。PC で記録を通して確かめ、直したものがそのまま実機の動作になるようにする。

- 新しいクレートは作らず、`crates/touch_algo` の中でファイルを分ける（`electrode.rs`・`touch.rs`・`playinfo.rs`）。使うところが同じ（ファームの `touch_task` と qubit_etude）で、必ず「信号処理 → 解析」の順につないで使うため。どちらも no_std・依存無し・ホストでテストする
- 名前の付け方（2026-11-08 決定）: 電極 1 つの単位のものは **electrode**、指 1 本の単位のものは **touch**。ファームの定数（`TOTAL_QT_KEYS` など）と `src/touch/`（`read_touch.rs` など）は AT42QT1070 の用語（key）のまま（§9）
- 電極数は `TouchTracker<P>` の `P`（ファームは `[u16; N]`、PC は `Vec<u16>`）の長さで決まる。電極数が 0 のときは何もしない（PC 向け）

### 7.1 qubit_etude での表示

- `algo.rs`（`AlgoRunner`）: 信号処理の後、同じフレームで output を `TouchTracker` → `PlayInfo` に渡して解析する。タッチポイント毎の (position, depth) と、出てきたイベントを時刻と一緒にためる。ファームと同じ条件にするには、間引きを 10ms にする
- GUI の右の欄の「タッチ」タブ: Touch1〜4 の position（触れていなければ ---）と depth。その下に、PC の解析が出したイベント（表示範囲、新しい順に 10 件。行数は固定）
- 下のバー表示（output）のすぐ下に、タッチのグラフ（`touch_plot`）。触れている指毎に、position の位置に円を描く。面積は depth に比例する（depth が `TOUCH_FULL_DEPTH`（200）で半径がグラフの高さの 0.45 倍、最小 3px）。円は周縁ほど薄く、色は指の番号毎で、中心に番号（1〜4）
- `replay_algo`: PC の解析のイベントと、記録の中のファームのイベントを並べて出す

## 8. 確かめ方

- qubit_etude の記録（`.qlog`）を `replay_algo` に通して、変更の前と後のイベントを比べる。PC で確かめてからファームに入れる
