# ハードウェアの改修 設計書

- §1〜§7 は 1 回目の改修（OLED を I2C1 から I2C0 に移す）。実施済み
- §8 は 2 回目の改修（96 キー向け。I2C0 をセンサーに使い、OLED とスイッチを PIO の I2C に移す。2026-11-14 決定）

## 1. 目的

- OLED（SSD1306）を、タッチセンサと同じ I2C バス（I2C1）から外し、別の I2C バス（I2C0）に移す
- OLED の転送がタッチのスキャンを止めないようにする（`doc/task_architecture.md` §2.2 の P1）
- I2C のロックアップ（`doc/i2c_problem260802.md`）が起きたときに、OLED が巻き込まれないようにする。エラーを表示できるので、原因の切り分けにも役立つ

ファームウェア側の対応は `doc/task_architecture.md` の段階 3 で行う。

## 2. 変更内容

### 2.1 ピンの割り当て

| 機能 | 改修前 | 改修後 | 備考 |
|---|---|---|---|
| I2C1 (400kHz) | SDA=GP6 (D4), SCL=GP7 (D5) | 変更なし | PCA9544 ×4 (0x70–0x73) のみになる |
| **I2C0** | 未使用 | **SDA=GP0 (D6), SCL=GP1 (D7)** | **SSD1306 OLED (0x3C)**。D6 / D7 は表面のピンで、今の基板では空いている |
| NeoPixel | GP5 (D3) | 変更なし | |
| ADC | GP26/27/28 (D0/D1/D2) | 変更なし | |
| スイッチ | GP2 (D8), GP4 (D9) | 変更なし | 2 回目の改修で PCF8574 に移す（§8） |
| 内蔵 LED | GP25 | 変更なし | |
| UART1（予備） | GP20 (D12) / GP21 (D11) 未使用 | 未使用のまま | 裏面のパッド。USB が動かないときのデバッグ用に、必要になれば使う（TX1 = GP20、RX1 = GP21） |

- RP2350 の GP0 / GP1 は、I2C0 の SDA / SCL に割り当てられる
- 常に使う OLED は、配線しやすくはんだ付けの信頼性も高い表面の D6/D7 に置く。使うかどうか分からない UART の予備は、裏面の D11/D12 に回す（裏面のパッドの割り当ては Seeed の資料による）
- D6/D7 が今の基板で空いていることは確認済み

### 2.2 作業

1. OLED の SDA・SCL の配線を、今の I2C1 のバスから外す
2. OLED の SDA を D6（GP0）、SCL を D7（GP1）につなぐ
3. OLED の電源（3.3V・GND）は今のまま
4. I2C0 のバスにプルアップを用意する（§3）

## 3. プルアップ

### 3.1 現状

- I2C1 のバスには、これまで基板側でプルアップを付けている
- OLED モジュールもプルアップ抵抗を載せている可能性が高い（多くのモジュールは 4.7kΩ や 10kΩ を載せている）。その場合、今の I2C1 は **基板側と OLED 側のプルアップが並列（二重）** になっている
    - 例: 4.7kΩ と 4.7kΩ の並列なら約 2.35kΩ、4.7kΩ と 10kΩ なら約 3.2kΩ

### 3.2 改修による変化

| バス | 改修後のプルアップ | 影響 |
|---|---|---|
| I2C1（タッチ） | 基板側だけになる | OLED 側の分が外れるので、プルアップが弱くなる（抵抗値が上がる）。信号の立ち上がりが遅くなる。400kHz で PCA9544 ×4 とケーブルがつながるバスなので、余裕が減っていないかを確認する（§4 の #5） |
| I2C0（OLED） | OLED モジュールのプルアップだけ | モジュールにプルアップがあれば追加は不要。無ければ 3.3V へ 4.7kΩ 程度を追加する |

- I2C1 の立ち上がりが悪くなった場合は、基板側のプルアップの抵抗値を下げる（例: 4.7kΩ → 2.2kΩ）。3.3V・2.2kΩ なら流れる電流は約 1.5mA で、I2C の規格（Fast-mode で 3mA まで）に収まる
- プルアップの強さが変わると、I2C のロックアップ（`doc/i2c_problem260802.md`）の出方が変わる可能性もある。改修の前後で、ロックアップの起きやすさに変化が無いかも見ておく
- RP2350 の内蔵プルアップは弱すぎる（数十 kΩ）ので、400kHz の I2C には頼らない

### 3.3 確認の方法

- OLED モジュールの裏面を見て、SDA/SCL に抵抗がつながっているか、その値はいくつかを確かめる
- 電源を切った状態で、SDA/SCL と 3.3V の間の抵抗値をテスターで測る
    - 改修前（二重の状態）と改修後（I2C1・I2C0 それぞれ）で測って記録しておく

## 5. ファームウェアとの対応

- **改修後の基板では、`main` ブランチのファーム（OLED を I2C1 で使う）は OLED が表示されない**。OLED の初期化に失敗し、エラー 51（`main` のファームでの OLED 初期化エラーの番号）が表示される。タッチ・MIDI・LED は動く
- 逆に、段階 3 以降のファームを改修前の基板で動かしても、OLED は表示されない（エラー 42。段階 3〜5 のファームでは 51）
- 基板とファームの組み合わせを取り違えないよう、改修した基板には印を付けておく
- 改修後は `CLAUDE.md` のハードウェア構成の表を更新する（I2C0 の行を追加し、I2C1 の行から OLED を外す）

## 8. 2 回目の改修: I2C0 をセンサーに使い、OLED とスイッチを PIO の I2C に移す（2026-11-14 決定）

### 8.1 目的

- 96 キーを 1 系統の I2C で読むと、スキャンに約 20ms かかり、10ms の周期に収まらない（`hw96_check.md` §2.1）。AT42QT1070 のクロックストレッチで、チップ 1 個の読み込みに約 1.2ms かかるため
- ハードウェアの I2C0・I2C1 を両方ともセンサーに使い、PCA9544 を 2 台ずつに分けて、2 系統を同時に読む（平均約 10ms の見込み）
- 空いているピンが無いので、空いていた GP3 とスイッチに使っていた GP4 を PIO の I2C にし、OLED とスイッチ用の GPIO エキスパンダー（PCF8574）をそこにつなぐ。決めた経緯は `hw96_check.md` §2.2
- OLED をセンサーと別のバスにする理由（§1: OLED の転送がスキャンを止めない、ロックアップに OLED を巻き込まない）は保たれる

### 8.2 ピンの割り当て

| 機能 | 改修前（1 回目の改修の後） | 改修後 | 備考 |
|---|---|---|---|
| I2C0 (400kHz) | SDA=GP0 (D6), SCL=GP1 (D7): OLED | **同じピンで、センサー（PCA9544 2 台）** | |
| I2C1 (400kHz) | SDA=GP6 (D4), SCL=GP7 (D5): センサー（PCA9544 4 台） | 変更なし。センサー（PCA9544 2 台） | |
| **PIO の I2C** | 無し | **SDA=GP3 (D10)、SCL=GP4 (D9)** | SSD1306 OLED (0x3C)、PCF8574 (0x20) |
| スイッチ | GP2（右）・GP4（左）に直結。プルアップ、Low で押下 | **PCF8574 の P0（左）・P1（右）** | Low で押下は変わらない |
| NeoPixel | GP5 (D3) | 変更なし | |
| ADC | GP26/27/28 (D0/D1/D2) | 変更なし | |
| 内蔵 LED | GP25 | 変更なし | |
| GP2 (D8) | スイッチ（右） | **空き（予備）** | 表面のピン |
| UART1（予備） | GP20 (D12) / GP21 (D11) 未使用 | 未使用のまま | 裏面のパッドはすべて予備のまま |

- GP3 と GP4 はハードの I2C の組にならない（GP3 は I2C1 の SCL、GP4 は I2C0 の SDA）ので、PIO で I2C にする
- SCL を SDA の隣のピン（SDA + 1）にしたのは、pico-examples の `i2c.pio` がその前提で書かれていて、そのまま使えるため（`hw96_check.md` §2.2）
- 配線はすべて表面のピンで済む
- PCF8574 のアドレスは 7 ビットで 0x20〜0x27。TI のデータシート（PCF8574DWR など）の 0x40〜0x4F は、R/W のビットを含めた 8 ビットの書き方で、同じもの
- PCF8574**A**（0x38〜0x3F）は OLED の 0x3C とぶつかることがあるので使わない。PCF8574（A 無し）を使う
- PCF8574 の P2〜P7 は空く。後でスイッチや LED を足せる

### 8.3 作業

1. スイッチ 2 つを GP2・GP4 から外す。GP4 の線にあるスイッチ用の部品（プルアップ抵抗、チャタリング対策のコンデンサなど）も外す。特にコンデンサが残ると I2C の波形が崩れる（回路図 `mcuboard_schematic.pdf` で確かめる）
2. OLED の SDA・SCL を、D6/D7（GP0/GP1）から外し、SDA を D10（GP3）、SCL を D9（GP4）につなぐ
3. PCF8574 を GP3・GP4 のバスにつなぐ。電源は 3.3V。A2〜A0 をすべて GND にして、アドレスを 0x20 にする。INT は使わない（100ms 毎にポーリングする）
4. 左のスイッチを P0、右のスイッチを P1 と GND の間につなぐ。PCF8574 のピンは弱いプルアップ（約 100µA の電流源）を内蔵しているので、外付けのプルアップは無くてもよい
5. GP3・GP4 のバスにプルアップを用意する。OLED モジュールのプルアップがあればそれでよく、無ければ 3.3V へ 4.7kΩ 程度を追加する（§3 と同じ考え方）
6. D6/D7（GP0/GP1）を、PCA9544 2 台のセンサーのバス（I2C0）につなぐ。I2C0 のバスにも基板側のプルアップを付ける（OLED を外すと、OLED モジュールのプルアップも無くなるため）
7. PCA9544 4 台を、I2C0 に 2 台・I2C1 に 2 台に分ける。バスが分かれるので、各バスで 0x70・0x71 を使ってもよい

### 8.5 ファームウェアとの対応

- ファームの対応の設計は `hw96_firmware261114.md`
- **改修後の基板では、今のファーム（OLED を I2C0、スイッチを GP2・GP4 で使う）は OLED もスイッチも使えない**。逆に、改修後のファームを改修前の基板で動かしても、OLED もスイッチも使えない
- 1 回目の改修と同じく、改修した基板には印を付け、改修後は `CLAUDE.md` のハードウェア構成の表を更新する（I2C0 をセンサーに、PIO の I2C の行を足し、スイッチを PCF8574 に）
- 今の基板（センサーは I2C1 だけ）でも、OLED とスイッチだけを先に移せば、PIO の I2C と PCF8574 のファームを確かめられる
