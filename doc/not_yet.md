## 2. 仮の値のまま（実機と SWAM で決める）

- **Note On**: `NOTE_ON_DEPTH`、`FLICK_DEPTH`、下がり始めの判定の幅、上限の時間
- **ベロシティ**: 110 になる時間 `VELOCITY_FAST_US`（10ms）、はじいたときの `VELOCITY_FLICK`（90）
  - はじいたときは、最大の depth の手前で上がり方が鈍る分だけ遅く見える。困ったら、周期毎の上がり幅が最も大きかった所の傾きを使う（touch_analysis §4.2）
- **ビブラート**: CC1 と CC19 への変換（×64・×10）、山と谷の差のしきい値（0.3 電極）、終わりの判定（2 倍）
  - 指が 2 本のとき、どちらの指を使うか（今は depth が最大の指）
- **ポルタメント**:
  - 動いていないとみなす速さ（2 電極/s）、取り直す時間（50ms）、区間の上限（500ms）
  - 速さからベロシティへの表（2 電極/s で 1 〜 20 電極/s で 110）。ベロシティとポルタメントの時間の関係や、レガートとの境目（Portamento Max Time で変わる）は SWAM のマニュアルに書かれていない
- **Expression**: depth から CC11 への変換テーブル（今は depth をそのまま使っている）
- **タッチの層**: k = 5、`TOUCH_ON_DEPTH`。どちらも `touch.rs` の定数で、qubit_etude からは変えられない。変えられるようにすると、記録を見ながら決めやすい

## 3. 決めていない仕様（演奏で困ったら対応すると決めてあるもの。2026-11-14、ユーザー）

- **離す速さ**（`PlayInfo::release_us`。測る仕組みはできている）を何の MIDI に使うか。音の消え方は Note Off より前に決まるので、Note Off のベロシティでは遅い。Expression が depth に付いて下がるので、それで足りるかを先に見る。足りなければ、先に Note Off を出して音源のリリースで伸ばす（SWAM なら String Resonance などに CC を割り当てる）、などを考える（touch_analysis §4.2）
- **指 1 本 ↔ 2 本の変化**（touch_analysis §3.7.1 でも残るもの）
  - 2 本になった瞬間、続いている指の position が跳ぶのを Move にするか（分かれた直後はしばらく Move しない、など）
  - 1 本になった瞬間、どちらのノートを残すか（先に鳴っていたほう、など）、残らなかった指の Note Off をいつ出すか、残った指が真ん中に跳ぶのを Move にするか
- **軽いタッチで端の電極が落ちる**: k = 5 は、軽いタッチでは端の電極を落としやすく、position が電極の位置に寄る（`qubit_20261111_225627.qlog` で、電極 10 の output 3〜5 が区間に入らず、position が 11.00 に張り付いた）。k を下げるか、区間を決めたあと前後 1 電極を足すか（touch_analysis §3.4）
- **離した後に output が残ると、指が離れない**: k が OFF のしきい値になっているため（同じ記録で、最後まで電極 11 が 7〜8 のままだった。指がまだ軽く触れていたのかは分からない）。保持の最大時間を設けるか、OFF のしきい値を k と分けるか（touch_analysis §3.4）
- **2 本の指の間が k 以下にならないとき**: 幅が §3.7 の距離を大きく超える区間を、谷で分けるか。分けないと 1 本になって position が真ん中に出る（touch_analysis §3.7）
- 記録（`.qlog`）で確かめること: 区間の幅の分布、触れていない所に残る k を超える電極の数、2 本の指の間が k 以下になっているか

## 4. コードを読んで見つけ、まだ直していない問題（2026-11-08）

「確実」はコードから必ず起きると言えるもの、「おそれ」は条件によって起きるもの。

1. **noise_floor の大きい電極（おそれ）**: output は `delta − noise_floor` なので、noise_floor の大きい電極（etude の key5 は 11〜13、他は 1〜2）は、同じように触れても output が小さい。position がその電極から離れる向きにずれ、depth も小さくなる。output が k 以下に落ちると区間が 2 つに分かれる（touch_analysis §3.7.1 の距離以内ならまとまる）
2. **電極による感度の違い（おそれ）**: noise_floor の他に、電極の大きさ・配線の長さ・チップ毎の違いで、同じ触れ方でも delta の大きさが電極で違う可能性がある。position の偏りになる（96 電極の基板での確認は `hw96_check.md` §3）
3. **離れてから 20ms は同じタッチ（確実）**: 離れても `RELEASE_WAITING_US` の間は TouchPoint が残るので、その間に `CLOSE_RANGE`（3 電極）以内を叩き直すと、新しいタッチにならない。同じ電極を叩き直すと Note On が出ない（連打が抜ける）。近くの電極を叩くと Move になる
4. **結び付けが貪欲法（おそれ）**: 候補を depth の大きい順に、その時点で最も近い TouchPoint に結び付ける。2 本の指が近づいたとき入れ替わることがある。touch_analysis §3.7 の距離以内の指はまとめるので、起きうるのはそれより離れた指どうしだけ

## 5. 未実装・保留の機能

- **触れている間のノイズへの対策**（touch_baseline §3.12 の終わり）。指を止めた key5 の上の揺れは、ノイズの少ない電極の約 2 倍だが、演奏への影響は小さいと判断した（2026-11-21、ユーザー）ので、急がない。入れるなら、次のどれか（まだ選んでいない）
    1. 変化の速さで効き方を変えるフィルタ（One Euro Filter のようなもの）: 小さく遅い変化は強くならし、速く大きな変化はほとんどならさない
    2. 使う側でならす: 電極の層と depth は今のままにし、ならした値が要る所（ビブラートなど）だけ演奏情報の層でならす。速さの計測には、ならす前の depth を使う
    3. 電極毎の IIR: 境目の電極だけ時定数を長くする。いちばん簡単だが、揺れは数十〜数百 ms と遅いので時定数を数百 ms にする必要があり、本当に触れたときの立ち上がり（touch_analysis §4.2 の触れる速さ）も同じだけ鈍る。どの電極が境目かの設定も要る（96 キーでは境目が各所にできる）
- **Expression に揺れを足す案**（2026-11-21、ユーザー。案として記録）: key5（チップの境目）の上で弾くと CC11 が揺れ、SWAM では若干目立つが、むしろ弓で弾いたようなリアルさになった。そこで、同じような揺れを全体に足す
    - 足す所は電極ではなく、`PlayInfo` が depth から CC11 を作る所。電極に足すと、noise_floor の自動計測がその揺れも測って感度が落ち、position（ビブラートの判定・ノートの境目）や Note On のベロシティも乱れるため
    - 96 キーではチップの境目が 6 電極毎にあり、境目の電極だけが揺れる。全体に同じ揺れを足せば、その不安定さを隠すことにもなり、どこを弾いても音の感じがそろう
    - 揺れの目安（`qubit_20261121_120601.qlog`、指を止めた key5 の上）: depth の約 3%（106 に対して ±3 ほど、p-p 23）、速さは数十〜数百 ms。ノイズの少ない電極は約 1.5%（±1.5 ほど、p-p 10）。depth に比例した量の、ゆっくりしたランダムな揺れにする
    - 量（0 で止める）と速さを定数にし、qubit_etude で変えて聴き比べられるとよい
- Piano の処理（動作モードを無くした後、後で足す予定）
- MIDI で受けたノートをリングの LED に出す処理（`SHOW_RX_NOTES` = false で止めてある）
- Bow Pressure（CC80）。圧力センサを ADC につなぐまで止めてある
- ファームの値を PC に送る PROC と、PC からパラメータを変える `set` コマンド（2026-10-03 に見送り）
- qubit_etude の A/B 比較（パラメータの組を 2 つ持ち、同じデータに通した結果を重ねて表示する。debug_env §4.6）。今は `replay_algo` で変更の前と後のイベントを比べている
